# Loon 去广告精简版 · 2026-11-08

本次交付为两份自包含 Loon 插件：`Splash-Only.lpx`（开屏广告）与 `InApp-Ads.lpx`（应用内广告）。它们都没有 JavaScript、定时任务、远程 jq、媒体缓存或额外网络请求。原来的 27 个插件继续保留；精简版位于同一仓库的 `lite/` 目录，使用独立导入地址。

这是一套缩小处理范围的候选替代版，不是已经测出省电百分比的版本。离线检查通过不代表手机上所有广告都能消失。仍须 Loon 导入与逐 App 实测，特别是微博 SDK 的原生正则替换、淘宝开屏 JQ、酷安等待时间以及新版 App 的响应结构。

## 先说结论

把 27 个插件拼成 1 个，本身不会明显降低相同规则的工作量。Loon 插件是子配置；真正值得削减的是：处理哪些域名的 HTTPS、哪些接口要读取整个响应、执行哪些 JS/加解密/Protobuf 解析、是否有重取网络请求，以及哪些非广告功能被顺带执行。

本版优先移除非广告行为，再缩小接口、主机和响应修改范围。原生 JQ 仍要读取、解析并重新编码响应，不能把“零 JS”理解为零开销或保证优于所有 JS 实现。少下载广告也可能节省流量和电量，最终要看整机对照结果。

## 两份插件怎么使用

1. 保留旧插件用于回退，但先停用原来的对应去广告插件。不要叠加旧版和新版比较，否则会有规则冲突、重复复写或脚本被复写遮蔽。
2. 将 `Splash-Only.lpx` 导入 Loon。显示名为“开屏广告”，15 个 App 各有开关，默认开启，豆瓣因原版兼容限制默认关闭。
3. **先只启用开屏版观察**。应用内版暂不启用，得到简单的去广告基线。
4. 需要应用内广告过滤时，再导入并启用 `InApp-Ads.lpx`。显示名为“应用内广告”，24 个 App 的开关默认全部关闭，按需打开。
5. 版本要求沿用现有插件：Loon 3.5.1(998) 或更新且支持本版新式 Rewrite 语法；沿用你已经安装信任的 MITM 证书，无需重新签发。不要误把关闭全局 MITM 作为保持本版效果的办法，HTTPS 路径/正文过滤需要解密。
6. 导入后先看是否有配置解析错误，再检查登录、页面滚动、评论、视频播放、订单/支付相关页面等正常功能。出现异常时，先关掉对应 App 的新开关；需要回退就停用新插件并恢复旧插件。

## 开关的重要限制

**App 开关关闭后，不再命中该 App 的复写；但该 App 的主机仍在此聚合插件的静态 MitM 名单里。** 因而不能承诺“关掉 App 开关，其网络处理开销归零”。应用内版全部开关关闭且不准备使用时，请直接停用整个插件。

只去开屏也仍可能解密列入名单的主机上的普通 HTTPS 流量；“只改开屏接口”和“只在开屏期间解密”不是同一件事。其他已启用插件和主配置中的域名也会影响最终解密范围。

开屏版还包含一组**静态域名规则**，用于拦截阿里妈妈广告链路：`tanx.com`（曝光、竞价）、`atanx.alicdn.com`（广告素材 CDN）、`adashx.m.taobao.com` 与 `h-adashx.ut.taobao.com`（效果回传）。这些规则不挂在任何 App 开关下，插件启用即生效，因此会同时作用于淘宝、闲鱼、优酷等阿里系 App；它们也不需要 MitM 解密。如果出现图片缺失或页面异常，先停用整个插件对照，再单独去掉 `atanx.alicdn.com` 这一条。

如果只使用少数 App，更省处理范围的方式是只保留这些 App 的规则：在这两份插件中删掉其他 App 的 `request if` / `response if` 行，再删除 `[MitM]` 段中对应主机。App ID 与主机对照见 `manifest.json` 的 `summary` 和各条规则的 `hosts`。豆瓣仍默认关闭。单独关掉开关适合临时排障；物理裁剪适合长期不用某些 App。

## 覆盖范围及明确删去的功能

开屏版包含：12306、高德地图、哔哩哔哩、酷安、豆瓣、闲鱼、京东、麦当劳、淘宝、百度贴吧、微博、小红书、小象超市、知乎、转转。

京东开屏规则依据 2026-11-07 用户抓包新增 `queryPagePopWindow` 响应处理：删除 `stayWindowModule`。该字段是启动期弹层承载模块，可能也包含非广告弹窗；抓包回放确认字段被移除，但是否对应你看到的开屏广告仍需在手机上验证。

闲鱼开屏规则依据 2026-11-08 冷启动抓包补入 `mtop.idle.idleadv.scene.restore`。抓包请求包含 `restoreStage=appLaunch`，而旧版仅匹配路径中的 `splash`，用户反馈仍会出现开屏。新规则已经受“闲鱼”开关控制；接口和启动阶段已由抓包确认，实际能否清除该开屏仍需在手机上复核。

12306 开屏接口依据同一日冷启动抓包从空 `{}` 改为成功结构 mock：启动位为 `placementNo=0007`，保留一个无效素材并设置 `advertParam.skipTime=0`。`skipTime=1` 已由用户真机确认有效；当前 0 秒为试验值，客户端可能将其钳制为约 1 秒，也可能触发自身兜底。若出现白屏或停留异常，关闭插件中的“12306”开关即可回退。

- 只纳入现有规则中能较明确分离的开屏接口或开屏字段。贴吧仅 `home_screen_ad`，不保证覆盖其他 SDK；淘宝只保留明确 splash 配置，不再截断通用 `cloudvideo.video.query` 或 `poplayer` 模板。
- 百度网盘、菜鸟、得物、滴滴、瑞幸、网易云、拼多多、顺丰、淘票票等原规则使用通用广告接口、通用配置或域名拦截，不能诚实地说“只影响开屏”，所以未放进严格开屏版。其中若在应用内版保留通用广告接口，可能同时影响开屏，但不作保证。
- 不存在一条通用规则，可以可靠去掉所有 App、所有版本的开屏而不影响其他内容。App 自带启动动画、广告被拦后的客户端倒计时也未必能仅靠网络规则消除。

应用内版包含 24 个 App，逐项见 `AUDIT.md`。三个没有纳入的 App：

- **YouTube**：原版本来就是去广告，但依赖 Protobuf 解析，以及 `*.googlevideo.com` 视频域名解密和 QUIC 回退。本轮零 JS 版不承诺替代它。需要视频去广告时，可以单独启用已有 YouTube 插件；这会重新引入相应开销，应单独比较观看时的整机掉电。不要把这一项记为“已优化保留”。
- **淘宝**：已在开屏版处理。旧版其余规则主要是跨 App 广告接口和通用活动模板，没有足够依据将其整理成淘宝内部广告过滤。
- **京东外卖**：原规则主要删除推荐、搜索、钱包和页面入口，缺少足以可靠区分广告的判据，整组移除。

重要的覆盖缩减：B 站不再处理 Protobuf 搜索/评论/动态等接口；贴吧只改广告配置，不再处理 Protobuf 信息流/帖子内容；微博仅覆盖列出的主要信息流与文章广告；小红书不再把所有非笔记搜索结果当广告；微信只保留公众号广告，不包含原来整包小程序。可能有更多残留广告，这是严格精简的代价。

非广告功能全部剔除：图片/实况/视频保存、去水印、会员外观、底栏精简、普通推荐隐藏、热搜清空、关闭连播、视频帖过滤、页面工具白名单、现金任务隐藏、网络连通性和证书校验修改、HTTPDNS 通用封锁。没有新增全局 QUIC 禁用规则。如果某个 App 使用 QUIC 绕过了过滤，要先抓该 App 的请求确认，再考虑局部回退，不能据此全局禁用。

## 怎么判断是否真的省电

截图记录的是 11 月 5 日约 09:29：Loon 5%，屏幕活跃 1 分钟、后台 1 小时 1 分钟。它反映的是 Loon 的应用级统计，不能分摊到某个插件，也不能把后台时长等同于 JS 执行时长。截图本身无法证明“插件 X 消耗了多少电”。

建议在相同 Wi-Fi/蜂窝条件、相近信号、亮度、温度及相近使用量下，分阶段记录：

| 阶段 | 启用内容 | 目的 |
| --- | --- | --- |
| A | Loon 正常代理，但停用全部去广告插件 | 观察代理本身与其他配置的基线 |
| B | 在 A 上只启用开屏版 | 测开屏处理带来的净变化 |
| C | 在 B 上只打开一个常用 App 的内部广告开关 | 测该 App 处理与少下载广告的净变化 |

可先做每组 30–60 分钟、相同浏览步骤的短测，再观察一段正常使用。一次百分点变化噪声较大，至少重复相近场景；不要用“今天全天”和“昨天截至早上”的不同窗口比较。记录整机起止电量、用机时间、播放/刷页面时长、网络条件和 Loon 数据；不要只看 Loon 的排名或一个百分比。

若 A 已有明显待机异常，新版去广告插件无法解决该基线问题，应继续检查主配置的节点健康检查/策略测速、订阅刷新、正在运行的抓包日志、连接失败与重试等实际记录。本次只审计了本地 27 个插件，没有取得手机的当前主配置、已保存开关、请求耗时、CPU 或能耗剖析。旧记录中的“广告平台拦截器”和“HTTPDNS 拦截器”不在这 27 份文件中，不能宣称已审计它们；若仍启用，对照试验时应单独停用并观察。
